# Chat 组件开发待办清单

本清单依据 [AI 组件与 Chat 界面需求](ai-components.md) 维护。勾选表示仓库内已有可查看的组件、Gallery 示例或接入文档。Gallery 使用演示过程函数和本地数据；真实模型、会话持久化、鉴权与文件服务仍由宿主应用实现。

## 已完成的起点

- [x] 将 `chat_bubble`、`chat_message_list`、`chat_sender` 分别放在 `src/components/chat/` 的子模块中并公开导出。
- [x] 在 Gallery 的「AI 组件」分类提供 Chat 组合页，以及三个组件各自的示例页和可展开代码。
- [x] 展示用户与助手消息、浏览器本地草稿和发送后最近一条消息；示例支持中英文。

## P0：补齐可用的基础聊天流程

- [x] 定义供 Chat 组合使用的消息数据约定：稳定 `id`、`role`、`status`、`content`；明确页面与可复用组件各自持有的状态。
- [x] 将 Chat 示例从“只显示最近一次发送”改为可追加多轮消息，并用稳定 ID 渲染每条消息。
- [x] 增加空会话欢迎区和建议输入示例；有消息后切换到消息列表。
- [x] 展示发送中、完成、失败、取消状态，并提供可操作的取消和重试示例。
- [x] 明确并实现输入框的发送与换行快捷键、发送后的焦点处理，以及新消息到来时的滚动行为。
- [x] 为上述状态补齐独立 Gallery 示例，检查窄屏布局、键盘操作和屏幕阅读器可识别的标签与状态。

**P0 验收：**在不连接模型的 Gallery 中，用户可以开始空会话、连续发送多轮消息，并查看和操作主要请求状态；交互不依赖页面刷新。

## P1：会话与服务端交互边界

- [x] 提供会话侧栏的展示组件和独立示例，覆盖列表、当前会话、新建与切换。
- [x] 用真实路由表达当前会话；评估以 Topcoat `#[shard]` 局部更新会话列表和历史内容。
- [x] 形成宿主侧发送、取消、重试操作的接入示例；服务端行为由宿主的 `#[procedure]` 或端点实现，组件库不绑定模型协议。
- [x] 为助手消息的增量输出定义更新方式，只更新正在生成的消息，并正确落到完成、失败或取消状态。
- [x] 明确从浏览器传入的参数校验、鉴权和会话数据持久化属于宿主职责，并在接入文档中给出边界说明。

**P1 验收：**示例能够按路由切换会话，并演示增量更新及结束状态；通用组件无需知道具体模型或存储服务。
