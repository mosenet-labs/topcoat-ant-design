## Rust toolchain

Topcoat 0.11.0 and this library's 0.11.0 release require Rust 1.99 or newer. This repository pins 1.99.1 in its root `rust-toolchain.toml`:

```toml
[toolchain]
channel = "1.99.1"
profile = "minimal"
components = ["rustfmt", "clippy"]
```

Applications using this library also need a compatible toolchain; Cargo does not inherit toolchain files from dependencies. With rustup, install the pinned version and then verify the compiler from your project directory:

```sh
rustup toolchain install 1.99.1 --profile minimal --component rustfmt --component clippy
rustup show active-toolchain
rustc --version
```

The `rust-version` field in `Cargo.toml` declares a minimum version; it does not switch compilers. If a build still uses 1.98.1, check explicit `cargo +1.98.1` commands, the `RUSTUP_TOOLCHAIN` environment variable, and rustup directory overrides. CI toolchain settings and Docker Rust base images also need a compatible version.

## 1. Add the Cargo dependency

Add this to your application's `Cargo.toml`:

```toml
[dependencies]
topcoat-ant-design = { version = "=0.11.0", features = ["router"] }
```

Version 0.11.0 uses Topcoat 0.11.0 and requires Rust 1.99+. When upgrading from 0.3.x, migrate the official Dropdown Menu `target`/`id`/`close` API as well. For local component development, you can also use a path dependency:

```toml
[dependencies]
topcoat-ant-design = { path = "../topcoat-ant-design", features = ["router"] }
```

A crate that only renders components and does not build a Router can omit the `router` feature.

## 2. Create a Topcoat module router

Use `app.rs` as the root of the route tree. Rust `mod` declarations select which route modules are compiled, and `module_router!()` derives URLs from module paths:

```text
src/
├── main.rs          # mod app;
├── app.rs           # mod dashboard; root of module_router!()
└── app/
    └── dashboard.rs # #[page] maps to /dashboard
```

Pages use pathless `#[page]` functions; shared shells use `#[layout]`. A root layout automatically wraps the pages below `app`:

```rust,ignore
// src/app.rs
mod dashboard;

use topcoat_ant_design::head_assets;
use topcoat::{
    Result,
    router::{Slot, layout},
    view::{View, view},
};

#[layout]
async fn root_layout(slot: Slot<'_>) -> Result<impl View> {
    Ok(view! {
        <!DOCTYPE html>
        <html lang="en">
            <head>
                <meta charset="utf-8">
                head_assets()
                topcoat::runtime::script()
            </head>
            <body>(slot)</body>
        </html>
    })
}
```

```rust,ignore
// src/app/dashboard.rs
use topcoat::{Result, router::page, view::{View, view}};

#[page]
async fn dashboard() -> Result<impl View> {
    Ok(view! { <h1>"Dashboard"</h1> })
}
```

## 3. Configure the Router and assets

`head_assets()` declares the component CSS and fonts used by a page. The host also loads the bundle generated by Topcoat and registers it with the Router. `app_assets` is a value created by the host:

```rust,ignore
use topcoat_ant_design::RouterBuilderUiExt;
use topcoat::{
    asset::{AssetBundle, RouterBuilderAssetExt},
    runtime::RouterBuilderRuntimeExt,
};

let app_assets = AssetBundle::load().expect("load Topcoat asset bundle");

let router = topcoat::router::module_router!()
    .runtime()
    .topcoat_ant_design()
    .assets(app_assets)
    .build();
```

For a single self-contained binary, construct `AssetConfig` in an `assets` module as the Gallery does and use `let app_assets = assets::config()?;`. Asset configuration is necessary for the CSS, fonts, and Runtime to load.

## 4. Register additional linked resources

Topcoat 0.9 registers procedures and shards as routes. `module_router!()` discovers module-derived pages, layouts, layers, and routes; register procedures and shards explicitly with `.route(name)`. `topcoat_ant_design()` registers the library's Fontsource routes:

```rust,ignore
let router = topcoat::router::module_router!()
    .route(gallery_reply)
    .route(message_region)
    .runtime()
    .topcoat_ant_design()
    .assets(app_assets)
    .build();
```

Full `.discover()` suits applications starting with an empty `Router::builder()`. Calling `.discover_routes()` after `module_router!()` may register module routes twice. Do not register the same font routes through both full discovery and `topcoat_ant_design()`.

## 5. Use components

Import components from `topcoat_ant_design`. The caller owns browser state through Topcoat signals:

```rust,ignore
use topcoat_ant_design::{NotificationTone, notification};
use topcoat::runtime::signal;

let notice = signal(cx, String::new);

<button @click=$(|_e| notice.set("Saved successfully.".to_owned()))>
    "Save"
</button>

notification(
    message: &notice,
    title: "Saved",
    tone: NotificationTone::Success,
)
```

Import icon constants from `topcoat_ant_design::icons` and render them with Topcoat's native `icon` component. See the [Icons API](https://docs.rs/topcoat-ant-design/latest/topcoat_ant_design/icons/index.html) for an example.

## Integration responsibilities

| Layer | Responsibility |
| --- | --- |
| `topcoat-ant-design` | Build Tailwind CSS; declare assets; provide the JetBrains Mono Fontsource, Iconify icons, and component APIs. |
| Host Topcoat application | Build the module router; load the asset bundle; serve static assets; register fonts; call `head_assets()`. |
| Business pages | Import components and pass state and actions through signals, bound attributes, and events. |

## Topcoat 0.11 localization

Built-in component labels use Fluent translations. Existing `language` props still default to English; pass `UiLanguage::current(cx)` to follow the host locale. Set that locale in a router `#[layer]` with `cx.with(topcoat::l10n::locale!("zh"))`. A context derived only inside a layout does not reach the page.

```rust,ignore
use topcoat_ant_design::{UiLanguage, json_viewer};

view! {
    json_viewer(value: &data, language: UiLanguage::current(cx))
}
```
